1. **[P1] Подключена PDF.js с известной уязвимостью выполнения JavaScript.**

   Код: [teacher.html:133](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/public/teacher.html#L133), [student.html:104](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/public/student.html#L104), [app.js:1135](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/public/app.js#L1135).

   Оба участника используют PDF.js 3.11.174. При загрузке документа параметр `isEvalSupported` не отключён ни в основном, ни в резервном пути. По [официальному advisory Mozilla, CVE-2024-4367](https://github.com/mozilla/pdf.js/security/advisories/GHSA-wgrm-67xf-hhpq), версии до 4.1.392 включительно позволяют выполнить JavaScript в контексте сайта при открытии специально подготовленного PDF с настройками по умолчанию. Исправление опубликовано в 4.2.67. Возможный источник документа — загруженный учителем сторонний учебный материал. HttpOnly не предотвращает выполнение запросов от имени пользователя через такой скрипт.

   Обновить библиотеку и worker согласованно до поддерживаемой исправленной версии. До обновления выставить `isEvalSupported: false` в обоих вызовах `getDocument`. Проверены версия и параметры в коде, а также официальное описание уязвимости; вредоносный PDF в рабочее приложение не загружался.

2. **[P1] Некорректное сообщение от участника может завершить процесс сервера.**

   Код: [annotation-utils.js:79](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/lib/annotation-utils.js#L79), [server.js:3500](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L3500).

В `stroke:preview` вызов валидатора находится вне `try/catch`. Ученик или гость с доступом к уроку может отправить сообщение через своё соединение и вызвать необработанный `TypeError`. Это затрагивает весь процесс, а не только его урок.

   Исключение воспроизведено на исходном обработчике; дополнительно вызван настоящий `Socket.prototype.dispatch` из установленной Socket.IO: процесс завершился с кодом 1. Валидаторы должны безопасно возвращать `false` на произвольный JSON. Аналогично проверить `isValidErasePath` и аргументы остальных событий, включая `null`; исключения и отклонённые Promise обрабатывать на границе событий.

3. **[P1] Отзыв доступа не останавливает уже открытые Socket.IO-соединения.**

   Код: [server.js:2876](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L2876), [server.js:883](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L883), [server.js:3509](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L3509).

   Пользователь и урок проверяются только при handshake и сохраняются в `socket.data`. Архивирование урока, деактивация пользователя и изменение списка участников не отключают сокеты и не обновляют их права. Обработчики чата и аннотаций продолжают использовать прежнюю идентичность. В проверке обработчика после `active=false` HTTP-политика уже запрещала доступ, но существующий сокет успешно сохранил новый штрих. Он также остаётся подписанным на события комнаты.

   При отзыве доступа отключать соответствующие соединения и обновлять авторизацию для значимых событий. Учитывать срок действия токена, изменение роли и парольные сбросы; если будет несколько экземпляров приложения, распространять отзыв между ними.

4. **[P1] Финансовые проверки допускают двойное расходование остатка.**

   Код: [server.js:1718](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L1718), [server.js:1763](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L1763), [server.js:1575](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L1575).

   Чтение суммарного остатка и вставка расходной записи выполняются раздельно. Два запроса могут одновременно прочитать одну доступную сумму и оба пройти проверку. На реальном коде обработчика с управляемой задержкой чтения воспроизведено: исходный взнос 100, два перевода по 80, оба ответа 201, итоговый остаток −60. Уникальные индексы не предотвращают это: переводы имеют разные UUID. Аналогичная схема используется для отметок занятий на разные даты и для удаления поступлений/распределений.

   Нужны атомарное условное изменение общего баланса и согласованная запись журнала. При использовании транзакций все операции, влияющие на один остаток, должны конфликтовать на общем документе баланса; простого переноса чтения агрегата и вставки разных записей в транзакцию недостаточно для исключения write skew. Добавить проверку конкурентных запросов и защиту от повторной отправки одной операции.

5. **[P1] Новые базы получают одинаковые встроенные учётные данные администратора.**

   Код: [server.js:3860](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L3860), [server.js:1877](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L1877).

   При отсутствии пользователя `admin` приложение создаёт активного администратора с фиксированными солью и хешем из публичного репозитория. Поэтому во всех новых установках один и тот же пароль; его знание для одной установки применимо к другим, а опубликованный хеш позволяет подбирать его без ограничений HTTP. Наличие хеша не означает раскрытия самого пароля, и подбор пароля не выполнялся. API изменения пользователей дополнительно исключает роль `admin`, поэтому сменить пароль этого пользователя через существующий маршрут нельзя.

   Первую учётную запись создавать через явную процедуру первоначальной настройки с уникальным секретом, добавить смену пароля администратора. Для существующих установок отдельно проверить, остались ли встроенные данные, и заменить их при необходимости.

6. **[P2] Ученик может удалить аннотации другого ученика.**

   Код: [server.js:3609](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L3609), [server.js:3637](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L3637), [server.js:3691](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L3691).

Условие актуально для группового урока или нескольких входов по гостевой ссылке.

7. **[P2] Страница контроля урока не может загрузить PDF из-за несовместимых версий.**

   Код: [monitor.html:65](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/public/monitor.html#L65), [app.js:14](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/public/app.js#L14).

В Chromium с фактическими файлами CDN воспроизведено: `The API version "4.8.69" does not match the Worker version "3.11.174"`. Резервный путь использует ту же библиотеку и worker, поэтому проблему не обходит.

   Вынести настройку PDF.js в общее место, использовать одинаковую исправленную версию API и worker на всех страницах. Добавить браузерную проверку загрузки настоящего PDF в роли наблюдателя.

8. **[P2] Сброс пароля не отзывает ранее выданные сессии.**

   Код: [server.js:1896](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L1896), [auth.js:61](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/lib/auth.js#L61), [session-context.js:49](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/lib/session-context.js#L49).

Воспроизведено принятие старого токена после замены парольных данных. Похищенная сессия продолжит работать до исходного срока, который по умолчанию составляет 30 дней. Logout тоже очищает только cookie в текущем браузере.

9. **[P2] Закрытые PDF разрешено кэшировать в общих HTTP-кэшах на год.**

   Код: [server.js:2302](https://github.com/SergeyJak/Shool-app/blob/f687d06912941fb6163f9df7c3acf353a8cb5079/server.js#L2302).

   Авторизованный ответ `/api/document/file` получает `Cache-Control: public, max-age=31536000, immutable`. URL содержит документ и урок, но не пользователя; `Vary: Cookie` отсутствует. Это явно разрешает общему кэшу повторно использовать PDF для того же URL без обращения к проверке доступа на сервере. На общем устройстве также возможна выдача браузером ранее сохранённого файла после выхода. Наличие такого кэша в текущем production не проверялось: проблема подтверждена на уровне серверных заголовков.

   Для конфиденциальных файлов использовать `private` с обязательной повторной проверкой или `no-store`, в зависимости от требований к хранению на устройстве. Проверить также ответы с byte ranges. При наличии CDN учесть очистку уже сохранённых публичных ответов.
