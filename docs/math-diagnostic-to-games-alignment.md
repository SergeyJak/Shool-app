# Связь диагностики v2 с картами 1–20 и уровнями 1–100

Статус: аудит существующего кода и требования к будущей реализации. **Не изменяет работающую диагностику и не объявляет неподтверждённые навыки освоенными.**

Источник: `lib/math-diagnostic-v2.js`; образовательная программа: `docs/math-adventure-100-games-roadmap.md`.

## Что реально измеряется сейчас

| Ключ диагностики | Фактические вопросы | Ограничения |
| --- | --- | --- |
| `numbers` | сравнение двух целых чисел | нет состава числа, разрядов, числовой прямой |
| `arithmetic` | вычитание, затем умножение, затем выражения со скобками | нет отдельной оценки сложения, деления, письменных вычислений |
| `wordProblems` | задачи на вычитание, умножение, сдачу | нет независимой оценки многошаговых задач |
| `fractions` | нахождение дроби от целого | нет сравнения дробей, эквивалентности, действий, десятичных дробей |
| `geometry` | периметр и площадь прямоугольника | нет распознавания фигур, углов, построения |
| `measurements` | часы→минуты, метры→сантиметры, время поездки | нет массы, объёма, календаря |
| `patterns` | арифметические последовательности | нет таблиц данных, логики, диаграмм |

У каждого навыка банк содержит 30 вопросов, всего 210; максимум 42 ответа на диагностику. Оценка `difficulty` внутри одного ключа **не равнозначна доказанному владению всеми его подтемами**. Итоговый `level` сейчас — среднее оценок 7 ключей, а не точная позиция на учебной карте.

## Правила назначения уровня

1. Не конвертировать средний `result.level` напрямую в номер стартовой игры, пока карта навыков не покрыта. Существующая формула может использоваться как ориентир, **не как подтверждение освоения**.
2. Хранить отдельно статус каждого конкретного навыка: `unknown`, `needs-practice`, `learning`, `mastered`; отсутствие вопросов означает `unknown`, а не `mastered`.
3. Подбирать стартовую обучающую игру по **первому необходимому пробелу**, учитывая зависимости (например, деление требует понимания умножения), а не отправлять всех на уровень 1.
4. Для неподтверждённых навыков предлагать короткое уточнение или обучающую игру, но не закрывать автоматически предыдущие карты.
5. Внутри мини-игры нет порога «8 из 10»: подсказки, объяснения и возможность повторить без штрафов.
6. После пяти игр — отдельная небольшая проверка по навыкам этой карты, с новыми вопросами. При затруднении предложить адресное повторение конкретных игр и повторную попытку.
7. Прогресс и результаты проверок должны сохраняться серверно; миграция существующих `unlocked`/`completed` без потери данных.

## Перед разработкой первой игры

- Ввести декларативный каталог 100 уровней с `skillIds`, `prerequisites`, `gameType` и `checkpointSkillIds`.
- Согласовать детальную матрицу навыков и добавить диагностику недостающих фундаментальных тем; для сложных тем допустима короткая проверка перед соответствующей картой вместо перегрузки стартовой диагностики.
- Написать тесты на покрытие каталога, зависимости, выбор первого пробела и переходные проверки.
- Затем реализовать игру 1 «Собери яблоки» и пройти мобильный UX и E2E.
