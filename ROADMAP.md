## Phase 3 — Multi-user foundation

Главная цель: уйти от одного общего урока и полностью изолировать данные и realtime между разными парами учитель/ученик.

- [x] сделать `lessonId` обязательным контекстом урока
- [x] Socket.IO rooms по `lessonId`
- [x] follow-mode только внутри конкретного `lessonId`
- [x] PDF/document state только внутри конкретного урока
- [x] аннотации хранить с `lessonId` и `documentId`
- [x] исключить пересечение данных между параллельными уроками
- [ ] один учитель может вести нескольких учеников
- [ ] один ученик может иметь нескольких учителей
- [x] доступ к уроку только для его участников и admin
- [x] кабинет показывает только уроки текущего пользователя
- [ ] быстрый переход «Продолжить урок»

Целевая модель:

```text
users
  ↓
lessons
  ↓
lesson_members
  ↓
books
  ↓
documents
  ↓
sessions
  ↓
annotations
```

Базовые идентификаторы для новых сущностей:

```text
userId
lessonId
bookId
documentId
sessionId
```

## Пока сознательно НЕ добавляем

Чтобы не превратить проект в перегруженный SaaS раньше времени:

- [ ] встроенный чат

- [ ] видеозвонки

Добавлять только при появлении реальной потребности.

## Критерии успеха Multi-user версии

1. Два и более урока могут идти одновременно и не видеть события друг друга.
2. Каждый пользователь видит только свои уроки, документы и историю.
3. Учитель может переключаться между учениками без смены аккаунта.
4. Ученик может заниматься с несколькими учителями.
5. PDF, страницы, аннотации и follow-state полностью изолированы по lesson/session.
6. После перезапуска Railway все данные остаются в MongoDB.
7. Добавление новых пользователей не требует изменений в коде или ручного создания отдельных страниц.
