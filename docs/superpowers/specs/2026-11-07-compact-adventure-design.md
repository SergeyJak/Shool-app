# Games that fit the available screen

The user supplied phone screenshots of level 16 split across two screens and requested compact games with all information visible without scrolling. The existing layout sets generous fixed padding/gaps and full-width square pictures, so a 360×800 viewport needs 1074px even for the first treasure task. The first six games have separate renderers and inline styles; games 7–100 share the runner and fourteen mechanics.

Use one scoped stylesheet after the existing game/map styles. Size pictures using viewport height as well as width, retain readable 18px prompts and 13px feedback, put the level name/counter on one line where possible, and keep helper/reset/back actions in one row. Remove duplicated captions and decoration where they consume play space. Hide verification controls after success; keep the solved picture and full explanation. Ordered results replace the duplicated disabled choice tray. Fraction pictures and controls sit side by side; directional controls use one row. Preserve the original visual palette and all curriculum, retry, keyboard, progression and save behavior.

Use natural content flow rather than overflow clipping, internal scrolling, text truncation or scaling the whole page. The map remains independently scrollable. Native browser zoom and the operating-system keyboard remain browser-controlled; finite screen space must not be enforced by hiding content.

This bounds the collection's visual size even during an unsuccessful attempt. Dense paint grids retain 24px cells, while small two/four-column puzzles use shorter boards. Coordinate boards constrain their height using their column/row ratio. Solved robot controls and full-row painting controls disappear after they become inactive, leaving the result visible.
