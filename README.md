# School App

Онлайн-уроки с общим PDF, рукописными и текстовыми аннотациями, чатом и аудио/видеосвязью. Учителя управляют уроками, материалами и домашними заданиями; ученики также проходят математическую диагностику и игровые задания. Администратор управляет пользователями, доступом и финансовым журналом.

## Запуск

Требуется Node.js **22.13+** и MongoDB. Для финансовых операций обязательны **replica set или sharded cluster с поддержкой транзакций**; подойдёт MongoDB Atlas. На standalone MongoDB финансовые записи возвращают `503 PAYMENT_TRANSACTIONS_UNAVAILABLE`: небезопасного обходного режима нет.

1. Выполнить `npm ci`.
2. Скопировать `.env.example` в `.env`. Заполнить `MONGODB_URI`, задать случайный `AUTH_SECRET` и параметры первого администратора `BOOTSTRAP_ADMIN_USERNAME`, `BOOTSTRAP_ADMIN_PASSWORD`. Использовать уникальный пароль от 16 символов. `AUTH_SECRET` хранить постоянным между перезапусками и одинаковым на всех экземплярах приложения.
3. Выполнить `npm start`, открыть `http://localhost:3000`.
4. Войти администратором. Ученики могут зарегистрироваться самостоятельно; учителя заполняют анкету и получают доступ после одобрения. Участники также могут входить по приглашению в конкретный урок.

`MONGODB_DB_NAME` по умолчанию равен `school_app`; `PORT` — `3000`. Необязательный `DATA_NAMESPACE` добавляет префикс коллекциям. При первом использовании пространства существующая логика переносит метаданные пользователей, уроков и материалов из базовых коллекций; файлы GridFS отдельно не копируются, поэтому это не полноценная копия среды. Для отдельной установки безопаснее выбрать отдельную базу.

Для сжатия больших PDF нужен Ghostscript (`gs`); Dockerfile устанавливает его. Без Ghostscript сохраняется оригинальный файл. PDF.js и worker поставляются из одной зафиксированной npm-зависимости через `/vendor/pdfjs`, внешняя CDN для просмотра не требуется.

## Обновление существующей установки

Сначала сохранить резервную копию базы и финансового журнала. Установить зависимости через `npm ci`; убедиться в поддержке транзакций и в соответствии версии Node.js.

Приложение больше не создаёт общие встроенные аккаунты `admin`, `Darya` и `Alisa`. Существующие пользователи и их данные сохраняются. Если у активного `admin` ещё остался исходный общий пароль, запуск остановится с указанием способа его замены. Есть два способа явной ротации:

- Указать `BOOTSTRAP_ADMIN_USERNAME=admin` и новый уникальный `BOOTSTRAP_ADMIN_PASSWORD`. При запуске будет заменён только распознанный старый общий пароль. Изменение этих переменных не перезаписывает пароль уже защищённого администратора.
- Через защищённое окружение передать `ADMIN_ROTATE_USERNAME` и `ADMIN_ROTATE_PASSWORD`, затем выполнить `npm run admin:password`. Команда использует те же `MONGODB_URI`, `MONGODB_DB_NAME`, `DATA_NAMESPACE`, меняет только пароль указанного существующего администратора и отзывает его сессии. Пароль нельзя передавать аргументом команды; скрипт не выводит его в журнал.

Проверить и заменить пароли ранее созданных демонстрационных учителя/ученика через администраторский интерфейс. Эти аккаунты автоматически не удаляются: у них могут быть реальные уроки и история. Администратор также может изменить собственный пароль через API `PATCH /api/admin/users/:id` с единственным полем `password`; менять через этот маршрут чужого администратора или отключать администратора нельзя.

Смена пароля и выход из аккаунта отзывают его ранее выданные сессии на всех устройствах. Существующие cookies совместимы до первой такой операции. Гостевой выход отзывает конкретную гостевую идентичность. При отзыве доступа локальные соединения отключаются сразу; другие экземпляры проверяют пассивные соединения каждые пять секунд, а значимые события — перед обработкой. Неперсистентные превью используют проверку не старше одной секунды. Истёкшие cookies отключают соединение по таймеру.

Прогресс приключения хранится отдельно для каждого подтверждённого аккаунта. Старое общее локальное хранилище не импортируется, потому что определить его владельца невозможно; серверная история сохраняется. Сохранение игрового результата передаёт ожидаемый `userId`, чтобы смена аккаунта в другой вкладке не записала результат другому ученику.

Закрытые PDF возвращаются с `Cache-Control: private, no-store`. Если раньше перед приложением был настроен кэширующий CDN/прокси, очистить ранее сохранённые публичные ответы `/api/document/file`. Материал нельзя физически удалить, пока на него ссылается действующий или архивный урок/настройка документа.

## Финансовый журнал

Все изменения взносов, распределений, занятий и счетов выполняются в MongoDB-транзакции с общей записью блокировки журнала. Это предотвращает одновременное расходование одного остатка разными запросами или экземплярами приложения. Импорт возможен только в пустой журнал и либо завершается полностью, либо откатывается полностью.

Формы взносов и распределений используют `Idempotency-Key`: повтор после неизвестного сетевого результата на той же странице возвращает исходную запись. Для API-клиентов заголовок необязателен, но рекомендуется: 8–128 латинских букв, цифр, `_` или `-`; повтор с другим содержимым получает `409 IDEMPOTENCY_CONFLICT`. После подтверждённого успеха новая операция получает новый ключ.

## Проверки

- `npm test` — модульные и контрактные проверки.
- `npm run test:integration` — временные MongoDB replica set/standalone, настоящий HTTP-сервер и Socket.IO: конкурентные списания, откат импорта, права, отзыв сессий, архивы. Первый запуск скачивает тестовый `mongod`; рабочая база не используется.
- `npm run test:pdf` — загрузка и отрисовка настоящего PDF для учителя, ученика и наблюдателя, включая резервный путь.
- `npm run test:math-progress` — изоляция аккаунтов и гонки ответов в браузере.
- `npm run test:math-adventure`, `npm run test:layout`, `npm run test:rtc-browser` — остальные браузерные проверки.

Браузерным проверкам нужен Chrome/Chromium; путь можно указать через `CHROME_BIN`. Новые проверки используют локальный HTTP. Часть прежних проверок открывает `file://`; управляемая политика браузера может блокировать такой запуск. Реальная связь между устройствами и совместимость с конкретными мобильными браузерами требуют отдельной проверки в целевой среде.

## Railway / Docker

Dockerfile устанавливает production-зависимости через `npm ci`. Указать переменные базы, постоянный `AUTH_SECRET` и первоначального администратора, если он ещё не создан. Все экземпляры одной установки должны использовать одинаковую базу, пространство коллекций и секрет. Данные PDF хранятся в MongoDB GridFS, а не на локальном диске контейнера.

WebRTC использует STUN по умолчанию. Для сетей, где прямое соединение невозможно, настроить `WEBRTC_TURN_URL`, `WEBRTC_TURN_USERNAME`, `WEBRTC_TURN_CREDENTIAL` либо `CLOUDFLARE_TURN_KEY_ID` и `CLOUDFLARE_TURN_API_TOKEN`.
